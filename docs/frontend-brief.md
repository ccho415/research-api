# 給 pen.dev 的前端設計簡報

> ⚠️ **這是 2026-09-05 交給 pen.dev 的設計簡報，不是實作紀錄。**
> 前端後來實際做出來的東西已經跟這份分歧——概念確認頁、文獻年份範圍、
> PubMed 補查那一行，這份都沒有。**要知道畫面現在長什麼樣，讀
> `frontend/index.html`，不要讀這一份。** 保留它是因為它記著版型的意圖
> 與當初的取捨理由，那些沒有寫在別的地方。（2026-09-10 註）

**產品**：研究方向發想系統的網頁前端
**要的東西**：**5 個畫面的版型**（①–⑤）。不是某一次執行的畫面，是**樣板**。
**語言**：介面繁體中文，學術術語與識別碼保留原文
**畫布尺寸**：每個畫面 1440 寬，高度依內容

> **這是版型設計，不是內容設計。**
> 使用者每次丟不同的研究題目進來，畫面上每一個字、每一個數字、
> 每一份清單的長度都會不一樣。**第 3 節是這份簡報最重要的一節**，
> 它規定版面必須怎麼跟著內容變。
>
> 功能行為在 `frontend-spec.md`，那份不含視覺、換風格時不動。

## 1. 視覺規格（從參考網站量出來的實測值）

### 顏色

反白文字          #F6EFE5   ← 黑底上的字是米白，不是純白
分隔線            rgba(0,0,0,0.2)  1.6px dashed
描邊              #333333   1.6px solid  ← 是 1.6px，不是 1px

**三塊大色塊**：

```

中文          Noto Sans TC  weight 500（內文）／700（標題）
等寬          IBM Plex Mono   只用在 id、數字、MeSH 代碼

**中文內文的字距是 0.05em**，行高 1.6–1.8。參考網站在日文上就是這樣設的，

20 / 500               卡片標題
15 / 500 / 0.05em      內文，行高 1.6
12 / 500               標籤、日期、藥丸內文
```

### 五個特徵——這五個就是那個網站的樣子，缺一個就不像

**① 巨大的有機色塊當背景**

不是「區塊有底色」，是**整段內容坐在一塊超大的彩色形狀上**，
那個形狀只有**一到兩個角是圓的、圓角半徑 200–400px**，其他角是直角。
色塊會**滿版出血**、會**跟上下段重疊**，有時候是一個直徑比畫面還大的圓。

一頁裡通常只有 2–3 塊。**這是最重要的一個特徵。**

**② 黑色圓形箭頭鈕**

40×40 正圓、`#000` 底、裡面一個米白 `#F6EFE5` 的 → 箭頭。
**文字標籤在圓圈右邊，不在圓圈裡。**

次要的是**藥丸外框鈕**：圓角全滿、1.6px 描邊、文字置左、箭頭在最右。

**③ 虛線分隔**

清單每一列之間是 `1.6px dashed rgba(0,0,0,0.2)`，不是實線。卡片內部切分也用虛線。

> ⚠️ pen 的 schema 沒有虛線描邊。請自己想一個做法（一排小矩形、或圖樣填充），
> 並在交付時說明你用了哪一種。**退回實線會讓整體偏硬，是最差的選項。**

**④ 不對稱單角圓角**

面板常常**只有右上角是 16px 圓角**，其他三個角是直角。
分頁標籤是「第一個左上角 8px、最後一個右上角 8px」。
**不要每個角都套同一個圓角值。**

**⑤ 扁平粗描邊的人物插圖**

全身、**黑色粗外框線**、平塗色、五官極簡（點狀眼睛，常常沒有嘴）。
髮色用飽和的芥末黃／藍／紫／綠／粉。
主視覺是**一排人並肩走**（橫幅式），不是單一個吉祥物。
其他地方用**兩人互動**的小圖。插圖不加陰影、不加漸層。

### 版面

- 內容欄最寬 1100，置中，左右留白 170
- 區塊之間的垂直間距很大（80–140）
- 頁尾是**近黑色的板塊，只有上面兩個角是大圓角**
- 右側邊緣有一個固定的黑色「選單」直立標籤

## 2. 這個產品在做什麼

使用者是**研究者**。他丟一個廣泛的研究題目進來，系統自動讀文獻、
找出「作者自己說還沒解決的缺口」、生出十幾個研究方向、兩兩比較排名次、
判斷可不可行、驗證有沒有人做過、讓兩個 AI 辯論一場，最後寫成一份可下載的報告。

**整條流程約 30–60 分鐘，中間絕大部分時間使用者不在場。**

所以前端不是「操作台」，是**一趟旅程**：

```
① 交題目 ─→ ② 確認概念 ─→ ┄ 系統自己跑 ┄ ─→ ③ 放行 ─→ ┄ 再跑 ┄ ─→ ④ 放行 ─→ ⑤ 報告
```

### 三種「停下來」的視覺強度，必須分得出來

| | 意思 | 視覺 |
|---|---|---|
| **⏸ 阻塞** | **系統停住等你按放行**，不按就永遠不動 | **坐在彩色大色塊上**、有黑色藥丸「放行」鈕 |
| **✎ 必填** | 系統在等你的輸入才能開始 | 米白面板 + 黑色藥丸鈕，沒有大色塊 |
| **👁 參考** | 給你看的，略過也沒關係 | 一般卡片，低對比，可收合明細 |

**⏸ 如果看起來跟 👁 一樣，使用者會把「在等你」誤判成「壞掉了」。**

## 3. 內容是動態的——版面規則（**最重要的一節**）

畫面上幾乎沒有任何東西是固定的。**每一次執行的題目不同，
文字長度、清單筆數、數字位數全部都會變，而且沒有上限。**

### 3.1 佔位文字怎麼填

槽裡放**通用佔位文字**，例如 `研究方向標題`、`MeSH 描述詞`、`缺少的變項名稱`。
**不要放任何真實或看起來像真實的研究內容**——那會讓人以為那是產品的一部分。

但**不要每一筆都填一樣長**。每一種清單裡至少要有：

- 一筆**很短**（例如 6 個字）
- 一筆**長到折成兩行以上**
- 一筆**極長**，用來證明版面撐得住

**長度不設上限。** 沒有「標題最多幾個字」這種規則，所以版面必須無條件容納。

### 3.2 文字一律折行，不准截斷

任何文字槽都**不得**用省略號截斷、不得溢出容器、不得被裁切。
容器高度**隨內容長**。

唯一的例外是專案列表那種一列一筆的清單，那裡可以截斷——
但**截斷的那份完整內容必須在別的地方看得到**。

### 3.3 清單筆數不固定，而且可能是 0

每一個清單都要能是 0 筆、1 筆、或很多筆。

- **0 筆時容器不可以塌掉**，要有一句話說明為什麼是 0
- **筆數很多時要能往下長**，用垂直捲動或全部展開，不要用固定高度

畫稿時每個清單畫 3–4 筆示意即可（只畫一般狀態），
但**排版方式必須是能長的那種**，不要用絕對定位或固定高度把它釘死。

### 3.4 數字的位數會變

論文數可能是 `3` 也可能是 `1,048,576`；費用可能是 `$0.03` 也可能是 `$12.40`。

- 數字一律用**等寬字**（IBM Plex Mono）
- 數字欄要**靠右對齊**或用 `tabular-nums`，位數變了不能讓整排跳動
- **不要為某個位數的數字量身訂做欄寬**

### 3.5 有些區塊的存在與否是動態的

例如「錯誤態」、「警告框」、「某一個等級是空的」這些區塊，
**有時候整個不出現**。

版面必須是**流式堆疊**的（上下相接、自動補位），
不能是「這個位置預留給警告框」那種固定格線——
不出現的時候會留一個洞。

### 3.6 什麼是真的固定的

只有這些可以寫死：

- 介面自己的文案（標題、按鈕字、說明句、欄位標籤）
- **可行性四個等級 A / B / C / D**——永遠是這四組，順序固定
- **報告的八個章節**——永遠是這八節，順序固定
- **流程的五個步驟**——固定

其餘全部是動態的。

## ③｜⏸ 審閱點三：可行性分級（**先做這一個**）

元素最多、最能看出風格對不對，所以第一輪只做這個。

### 標頭（坐在**珊瑚色大色塊**上，左上角 360px 圓角）

色塊上米白文字：

- 眉標：`⏸ 審閱點 ③ · 系統正在等你`（固定）
- 大標：`[一句話說明現在停在哪裡]`（固定文案，一到兩行）

### 主體：分級看板（米白面板浮在色塊上，只有右上角 16px 圓角）

**四組固定存在**，順序固定，即使某一組是 0 也要出現：

```
A   [等級定義，一行]                    [數量] 個
B   [等級定義，一行]                    [數量] 個
C   [等級定義，一行]                    [數量] 個
D   [等級定義，一行]                    [數量] 個
```

等級字母用大號 Montserrat。

**每一組底下是該組的方向清單**，筆數 **0 到很多都可能**：

```
┌──────────────────────────────────────────────┐
│ [研究方向標題 — 長度不設限，可能折三行]        │
│ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ │
│ 缺什麼   · [變項名稱一]                        │
│          · [變項名稱二]  ← 筆數不定，可能 0 筆 │
│ 去路     [一段散文：去哪裡拿、需要什麼權限、    │
│           多久、多少錢——長度不設限，會折多行]  │
│ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ │
│ ⓘ [這一列自己的但書，一到三行]                │
└──────────────────────────────────────────────┘
```

**注意事項**：

- **只有兩欄。** 「缺什麼」是清單（`feasibility.missing`），
  「去路」是一段散文（`feasibility.route_to_tier_a`）。
  **不要拆成「去哪裡拿／怎麼拿／多久／多少錢」四欄**——
  資料庫只有一個自由文字欄，那四欄畫得出來但永遠填不滿
- 兩欄的內容長度差很多，**要能各自折行**，不要做成等高的表格格子
- **但書屬於那一列**，不是整頁一句，而且**不可摺疊**
- 某一組是 0 時，那一組仍然出現，底下放一句說明（黃底小框）

### 證據區（低對比，可收合）

**視覺強度要明顯低於分級看板**——沒有色塊、沒有描邊、只用虛線分隔。
**摘要行永遠可見，只有明細可以收合。**

```
▸ 排名   [N] 個方向兩兩比過，[M] 場 · 順序翻轉率 [x.x%]
▸ 去重   [N] 組候選，判定 [M] 組重複
```

展開後：

**排名**——一列一個方向：`[名次]`（大號 Montserrat）、`[方向標題]`（可折行）、
`[分數]`（等寬）、一條水平長條。**筆數不定。**
底下一個虛線框放兩到三句方法說明（固定文案）。

**去重**——一組一張橫卡，**左右並排兩段完整的方向敘述**。
**兩邊都可能很長，都要能折行，卡片高度取兩邊較高的那一邊。**
中間一個判定藥丸，右下角一個藥丸外框小鈕。

### 放行區（面板底部，虛線隔開）

- 兩個數字輸入框並排：`要驗幾個方向`、`辯論幾輪`
- 一行灰字：`[往下的預估費用]`、`[剩餘預算]`
- **黑色藥丸鈕**：`放行，開始新穎性驗證 →`
- 旁邊藥丸外框鈕：`上傳資料清單`

## ①｜首頁 — 三種狀態在同一個 frame 上下堆疊

**頂部**（三種狀態共用）：極小的字標「research」在左上、右上是使用者頭像。細線分隔。

### 狀態 1：交題目

**主視覺**坐在**駝色大色塊**上（左下角 320px 圓角）。
左邊文字、右邊人物插圖（幾個研究者並肩走，各拿著放大鏡／論文／試管／筆電）。

- 眉標（珊瑚色，字距 0.2em）：`從一個題目開始`
- 大標（40/700）：`[產品的一句話主張]`
- 內文：`[兩到三行說明系統會做什麼]`

**表單**（米白面板，只有右上角 16px 圓角）：

| 槽 | 型態 | 備註 |
|---|---|---|
| `題目` | 多行輸入框 | **高度要能隨輸入長大**，不是固定兩行 |
| `領域` | 下拉 | |
| `預算上限` | 數字框，前綴 `$` | |
| `你手上有資料嗎？` | 三張可點的橫卡（不是小圓鈕） | 每張：標題 + 一行說明。選中態要明顯 |

第一張橫卡選中時**就地展開第 5 節的資料清單面板**（不跳頁）；
第二張選中時追加一行黃字說明。**這兩者都是動態出現的區塊**，見 3.5。

**右欄側邊**（淡沙色面板）：`接下來會發生什麼`，五列編號清單（固定五步）。
**第 03、04 兩列要有 ⏸ 標記。**

**行動**：黑色藥丸鈕 + 右邊一行灰字說明。

### 狀態 2：專案列表

- 區塊大標（Montserrat）：`Projects`
- 分頁列（不對稱 8px 圓角）：五個篩選
- 每列**虛線分隔**：`[日期]`、`[狀態藥丸]`、`[題目]`、`[費用]`、右側黑色圓形箭頭鈕

**筆數不定，0 筆時要有引導。**
題目在這裡可以截斷（見 3.2 的例外），但要能點進去看完整的。

狀態藥丸至少五種，其中：

- **`等你放行` 用珊瑚底、要最顯眼**——這一區存在的主要理由就是找出它
- **`已停止` 要跟 `失敗` 明顯不同**（灰色空心點）

### 狀態 3：進行中

坐在**森綠大色塊**上（右上角 400px 圓角），色塊上米白文字：

- 大標：`[一句話：正在跑，可以先去做別的事]`
- 內文：`[一個時間範圍 + 會怎麼通知你]`——
  **是範圍不是倒數**，例如「通常 30–60 分鐘」。
  **不要寫「還要 25 分鐘」，後端沒有那個數字**
- 一張插圖：兩個人物坐在一疊書旁看同一份文件

**下方（回到米白底）是階段清單**，一列一階段，虛線分隔：

```
[代號]  [階段名稱]        [狀態圖示] [狀態]    [該階段的產出數字或預估費用]
```

- 階段數固定（十列），但**右側那一欄的內容長度差很多**，要能折行
- 前四列（W2／採集／W1／W3）不歸鏈管，後六列才是鏈
- 「進行中」那一列有沙色底 + 左側珊瑚色粗線
- 會停下來等人的階段掛一個 `⏸` 小藥丸
- **進行中那一列右側不要放「15 個方向中的 11 個」這種階段內進度**——
  階段只在結束時回報一次，中途的分數是捏的

**右下角**小卡片：`[已花] / [上限]` + 一條細進度條。

## ②｜確認檢索概念（✎ 必填，**唯一非做不可的人工步驟**）

頂部細導覽列，右側五個小圓點表示流程進度。

- 大標：`[一句話：這幾個詞決定系統會讀到哪些文獻]`
- 內文：`[兩行說明可以改／可以刪／改完就不能改了]`

**警告框**（黃色淡底、只有左上與右下 24px 圓角、左邊一個三角驚嘆號）：
`[說明對不到 MeSH 會怎樣]`

### 概念卡 × N（**N 不固定，可增可刪**）

每張卡橫向三槽：

```
┌────────────────────────────────────────────────────────┐
│ 概念 [n]                                    ✎  🗑      │
│ [輸入的詞]  →  [MeSH 描述詞 + 代碼]  →  [論文數]        │
└────────────────────────────────────────────────────────┘
```

- 三個槽的寬度差很多：輸入詞短、描述詞中等、論文數是數字（等寬、靠右）
- **描述詞可能很長也可能是 `(null)`**

**其中一張要畫成錯誤態**（因為這是這個畫面存在的理由，屬於一般狀態的一部分）：
整張卡改珊瑚色描邊、`(null)` 標紅、論文數特別大且是珊瑚色，
下面一行說明，再用**虛線**隔開一個「換成這些試試」區——
**替代建議是動態的藥丸清單，數量不定**，每個藥丸內含 `[詞] [論文數]`。

清單末尾一個藥丸外框鈕 `＋ 新增概念`。

**下方**：一行灰字 `[預估會生出幾個查詢]` + 黑色藥丸鈕 `開始檢索 →`。

## ④｜⏸ 審閱點四：辯論紀錄（**與 ③ 同版型**）

頂部坐在**森綠大色塊**上（右下角 360px 圓角）。

- 眉標：`⏸ 審閱點 ④ · 系統正在等你`
- 大標：`[一句話說明辯論結果]`

**分頁列**（不對稱 8px 圓角）：**一個被辯論的方向一個分頁，數量不定。**

### 終止摘要（放最上面，虛線框）

```
漂移        [分數]   門檻 [門檻值]      ← 大字；超標時用珊瑚色
輪數        [實際] / [上限]
終止原因    [一句話]
未解決反對  [數量]
```

底下兩行固定的說明文案（解釋漂移是對照原始敘述算的、
終止由系統算出來而非模型自稱）。

方向題名下方一行 `[原始敘述]`（灰字、等寬、**可能很長，要折行**）。

### 逐輪紀錄（**輪數不定**）

一輪一張卡，左右兩半：

```
┌──────────────────────────────┬─────────────────────────────┐
│ ▌反對（森綠色左邊條）          │ ▌回應（駝色左邊條）    (5) │
│ [反對內容，長度不設限]         │ [回應內容，長度不設限]      │
│                              │ → [已解決／未解決]          │
└──────────────────────────────┴─────────────────────────────┘
```

- 右上角一個**評分圓章**（1–5）
- **兩半的內容長度會差很多**，卡片高度取較高的一邊，兩邊都要能折行

**評分分布**用小長條 + 一句固定說明。
**引用**一行小字：`引用 [N] 筆 · 捏造 [M] 筆`。

### 放行區

黑色藥丸鈕 `放行，產出報告 →` + 旁邊灰字 `[報告份數與預估費用]`。

## ⑤｜報告（含下載與撞題監看）

### 頂部（坐在駝色色塊上，左下角 300px 圓角）

- 眉標（米白）：`報告 [id] · [日期]`
- 大標（米白，36/700）：`[報告標題 — 長度不設限，可能折三行]`
- 三個藥丸橫排：`[新穎性判決]`、`[可行性等級]`、`[引用數 · 捏造數]`
  - 判決有四種值，**不同值要能看出差別**（綠／黃／珊瑚）
- **黑色藥丸鈕** `下載報告 (PDF)` + 藥丸外框鈕 `下載 (Markdown)`，浮在色塊右下

判決藥丸旁一行小字解釋那個判決的意思（**內容隨判決不同**）。

### 八節內容（**節數固定 8，順序固定**）

左側一欄固定的節次導覽（01–08），右側是內容。
每節之間**虛線**分隔。

**每一節的長度差非常多**——有的三行，有的三十行。
版面必須是流式的，導覽欄要能跟著捲動。

**第 06 節要多一個東西**：一個獨立的表格 `[要去弄什麼資料]`，
標題旁一個小藥丸 `直接從資料庫產生，不經模型`，
配一句固定說明。**表格筆數不定。**

**第 04 節**每一筆引用旁邊有 DOI / PMID 兩個小連結圖示。**筆數不定。**

### 「這份沒有涵蓋什麼」（黃底框，**不可摺疊**）

一個項目清單，`[筆數不定]`，每一筆長度不定。
**這個區塊永遠存在**，即使只有一筆。

### 撞題監看（頁面最底部一區，預設關閉）

- 一個開關 + 一句固定的成本說明
- 開啟後一行狀態列：`[查詢數] · [基線識別碼數] · [上次檢查時間] · [目前結果]`

## 6. 不要做的事

- **不要把任何一次執行的內容當成設計。** 槽裡放通用佔位文字。
- **不要假設任何文字的長度。** 沒有上限，一律折行，容器隨內容長。
- **不要用固定高度或絕對定位釘死清單。** 筆數會變，也可能是 0。
- **不要為某個位數的數字量身訂做欄寬。**
- **不要把 ③④ 的放行區做得跟證據區一樣強。** 證據可以略過，放行不行。
- **不要做成儀表板。** 這是研究者的旅程，不是維運的操作台。
  沒有系統健康度、沒有一排 KPI 磁磚。
- **不要每個角都圓。** 不對稱圓角是參考網站的識別。
- **不要用純白與純黑。** 底是 `#F4EDE7`，字是 `#333333`。
- **不要加陰影和漸層。** 層次靠色塊和描邊。
- **不要用 emoji 當區塊標記。**
