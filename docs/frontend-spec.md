# 前端功能規格（不含視覺風格）

**這份只講「要有什麼、怎麼運作」，不講長什麼樣子。**
配合任一份風格簡報使用；換風格時這份不動。

- **畫面數：5**（原本規劃 11 個，收斂的理由見第 2 節）
- 對應後端：W1–W10 + W-DATA
- 介面語言：繁體中文；學術術語、識別碼、數字保留原文

---

## 1. 系統模型（做任何畫面之前要先懂的三件事）

### 1.1 前端不直接打 API

`research-api` 在內網（`research-api.zeabur.internal`），**瀏覽器連不到**。
前端所有請求都送到 **n8n webhook**，由 n8n 持有憑證後轉發。
前端不儲存任何 API 金鑰。

### 1.2 整條鏈是非同步的，而且會自己往下跑

使用者交完題目之後，後端會自己接續跑六到九個階段，**總共約 30–60 分鐘**。
使用者絕大部分時間不在場。因此：

- 任何「開始」動作都是**發射後不等待**，立刻回到狀態畫面
- 前端靠**輪詢**取得進度（建議 10 秒一次），不是靠請求的回應
- 使用者可以隨時關掉分頁再回來，狀態必須完全從後端還原

### 1.3 整趟流程只有四個地方需要人

```
交題目 ──→ 確認概念 ──→ ┄┄ 系統自己跑 30 分鐘 ┄┄ ──→ ⏸③ 放行 ──→
       ┄┄ 再跑 ┄┄ ──→ ⏸④ 放行 ──→ 報告
```

**中間那些「看得到但不需要動作」的東西（去重結果、排名、階段進度）
不是頁面，是這四個畫面裡的區塊。**

## 2. 為什麼是 5 個畫面，不是 11 個

先前的規劃把每一種後端輸出都給了一個頁面。那是把「有這份資料」
誤當成「要一個頁面」。**判準應該是：使用者在這裡要不要做決定。**

| 原畫面 | 處置 | 理由 |
|---|---|---|
| A 交題目 | **保留 → ①** | 決定：題目、預算、資料狀況 |
| B 確認檢索概念 | **保留 → ②** | 唯一非做不可的人工步驟 |
| C 進行中 | 折進 ① | 同一頁的另一個狀態，不是另一個頁面 |
| D 👁① 去重 | 折進 ③ | 非阻塞。使用者回來時它早就跑完了 |
| E 👁② 排名 | 折進 ③ | 同上，**而且名次正是 ③ 要用的決策依據** |
| F ⏸③ 分級 | **保留 → ③** | 阻塞。決定：驗幾個、辯幾輪 |
| G 資料清單 | 折成面板 | 條件性旁支，出現在 ① 與 ③ 裡 |
| H ⏸④ 辯論 | **保留 → ④** | 阻塞。決定：放行、產幾份報告 |
| I 報告 | **保留 → ⑤** | 決定：下載 |
| J 專案列表 | 折進 ① | 首頁的一區 |
| K 撞題監看 | 折進 ⑤ | 選配功能，預設關閉 |

**D、E 折進 ③ 不只是省頁面，設計上更好**：去重與排名都在 ③ 之前就完成了，
使用者回來時它們已經是歷史。而 ③ 要他決定「往下驗哪幾個」——
名次就是做這個決定的依據。拆成兩頁等於把證據和決定隔開。

### ③ 和 ④ 共用同一個版型

兩者都是「系統停住了 → 看證據 → 調參數 → 放行」。骨架相同：

```
┌ 標頭：⏸ 系統正在等你 · 這是審閱點 N
├ 證據區（內容不同）
├ 但書區（不可摺疊）
└ 放行區：參數 + 預估費用 + 剩餘預算 + 放行鈕
```

**設計時畫一次版型、填兩份內容。**

## 2.5 兩條硬規則（動手前先套）

### 每個會變的元素都要說得出來源欄位

畫面上每一個會變動的東西，都必須對得到**一個實際存在的 API 欄位**。
對不到就是編的。

**這不是形式要求。** 實際踩過：C 級的「去路」畫成五欄，
但資料庫只有一個自由文字欄；報告的「這份沒有涵蓋什麼」與
「不經模型的取得清單」**根本沒被存下來**；進行中畫面的階段內進度和 ETA
**沒有任何來源**。這些在設計稿上看起來完全正常。

**寫死一個值只是第一層錯誤**——換成 API 欄位就能修。
**畫一個不存在的欄位修不掉**，後端得先長出那個東西。

對照結果在 `frontend-api-gaps.md`，做法是把畫面元素逐一對到
`main.py` 的端點與 `schema.sql` 的欄位。零成本，只讀程式碼。

### 每個槽都要標明它怎麼變

0 筆／很多筆、一行／十行、數字幾位數。版面要撐得住，
不能假設某一次執行的形狀。細則見第 3.1–3.6 節。

## 3. 跨畫面的共通規則

### 3.1 兩種審閱點，行為完全不同

| | 代號 | 系統行為 | 使用者不理它會怎樣 |
|---|---|---|---|
| **非阻塞** | 👁① 去重、👁② 排名 | 繼續往下跑 | 什麼都不會發生 |
| **阻塞** | ⏸③ 分級、⏸④ 辯論 | **停住，等放行** | **永遠停在那裡** |

收斂之後 👁①② 變成 ③ 裡的區塊，但**兩者的視覺強度仍然必須不同**：
證據區是可以略過的，放行區不是。

阻塞畫面必須讓「系統在等你」一眼看得出來。做不出來的話，
使用者會把「在等你」誤判成「壞掉了」。

### 3.2 導覽模型

- 進入點永遠是 **① 首頁**
- ②③④⑤ 由後端狀態決定現在該看哪一個
- 任何時候都要能回到 ①

**深連結**：每個畫面都要能用 URL 直接開（含 `project_id`），
因為通知信會直接連到「等你放行」的那個畫面。

### 3.3 狀態必須從後端還原

重新整理、換裝置、隔天回來，都要看到同一個狀態。
**不要把流程狀態存在瀏覽器。** localStorage 只用於無關緊要的偏好。

### 3.4 每個畫面都要有的四種狀態

| 狀態 | 規則 |
|---|---|
| **載入中** | 骨架屏，不要整頁轉圈——版面不能在資料到達時跳動 |
| **空** | 說出**為什麼**是空的、**接下來該做什麼**。不要只寫「沒有資料」 |
| **錯誤** | 說出哪一步失敗、可不可以重試，並提供重試動作 |
| **正常** | — |

**「空」的分辨很重要**：`0 篇論文` 可能是「查了但沒找到」也可能是「還沒查」，
兩者意義相反，畫面上必須說得出是哪一種。

### 3.5 數字一律附上分母與門檻

- 比例寫 `69 / 200`，不是只寫 `34%`
- 有門檻的把門檻並排：`漂移 [分數]（門檻 [門檻值]）`
- 預估值要標明是預估

### 3.6 費用要一直看得見

整條鏈有美元上限，超過會被護欄擋下（HTTP 402）。
每個畫面都要顯示「已花 / 上限」，會花錢的動作旁邊顯示預估費用。

**不要讓使用者按下一個註定被 402 擋掉的按鈕**——預估超過剩餘預算時
按鈕就要停用，並說明差多少、可以怎麼調整。

### 3.7 警語與但書不可摺疊

敘述永遠讀起來合理，警語才是決定該信多少的東西。
把警語藏進預設收合的區塊，等於只呈現說服力最強的那一半。

**但書屬於它所描述的那一列，不是整頁一句。**

### 3.8 可及性與響應式

- 所有操作可用鍵盤完成；焦點要看得見
- 顏色不可以是唯一的資訊載體
- 表格與長內容在自己的容器內橫向捲動，**頁面本身不得橫向捲動**
- 最小支援寬度 1024；1440 為設計基準

## 4. 五個畫面

---

## ①｜首頁（交題目 · 專案列表 · 進行中）

**同一個頁面的三種狀態。** 使用者從這裡出發，也從這裡回來。

### 狀態 1：交題目（新使用者，或按「開新專案」）

#### 必要欄位

| 欄位 | 型別 | 驗證 | 說明文字要講的事 |
|---|---|---|---|
| 題目 | 多行文字 | 必填，10–300 字 | 中英文皆可，一句話就好 |
| 領域 | 單選 | 必填，預設 `clinical` | 決定用哪些檢索來源 |
| 預算上限 | 數字（美元） | 必填，0.5–20，預設 2.00 | **整條鏈**的上限，不是單一階段 |
| 資料狀況 | 三選一 | 必填 | 見下 |

#### 資料狀況三選一（這一題決定後面兩段的行為）

1. **我有資料，之後上傳欄位清單** → 分級會針對使用者真的做得了什麼。
   選中時**就地展開資料清單面板**（見第 5 節），不跳頁
2. **我目前沒有資料** → 分級改問「要做到需要什麼」；**A 級結構上不可能**，
   下游看的等級是 B,C 而不是 A,B。
   **選中當下就要說清楚 A 會是 0**，不要等到 ③ 才解釋
3. **先停在排名，之後再說** → 鏈跑到錦標賽名次就停

#### 側欄：接下來會發生什麼

五步概覽，**必須標出哪兩步會停下來等人**。
使用者要在按下按鈕之前就知道自己之後要回來兩次。

#### 送出

- 按鈕旁顯示：`到確認概念為止不花錢`
- 送出後建立專案、跑概念拆解，導向 ②

---

### 狀態 2：專案列表（有既有專案時，排在交題目表單上方或下方）

一列一專案：日期、狀態、題目、已花費用、進入動作。

狀態至少五種：`進行中` / **`等你放行`** / `已完成` / `失敗` / `已停止`

- **`等你放行` 要最顯眼**，這是這一區存在的主要理由。
  導覽上要有計數提示
- **`已停止` 要跟 `失敗` 分開**——一條被使用者刻意結束的鏈，
  不應該看起來像卡住了

篩選：`全部` / `進行中` / `等你放行` / `已完成` / `失敗`

---

### 狀態 3：進行中（點進一個還在跑的專案）

**這個狀態的主要工作不是顯示進度，是讓使用者安心離開。**

必須明確傳達三件事：

1. **還要多久**（估計值，標明是估計）
2. **需要你的時候會通知你**（以及用什麼方式）
3. **現在可以關掉這一頁**

#### 階段清單

一列一階段：代號與名稱、狀態（完成 / 進行中 / 等待 / 失敗 / 已跳過）、
右側資訊。

- **完成的階段顯示實際產出的數字**（幾個查詢、幾篇論文、幾個方向）
- 等待中會花錢的階段顯示預估費用
- **會停下來等人的階段要事先標出來**
- 「進行中」那一列要能一眼找到
- 失敗的階段顯示錯誤摘要與「重試這一段」

輪詢間隔 10 秒；分頁不在前景時降頻。

跑到阻塞審閱點時自動導向 ③ 或 ④；跑完導向 ⑤。

## ②｜確認檢索概念（**唯一非做不可的人工步驟**）

**進入**：① 送出後。**離開**：按下「開始檢索」，回到 ① 的進行中狀態。

### 為什麼這個畫面存在

模型把題目拆成數個英文檢索概念，再對到 MeSH 主題詞。
**對不到 MeSH 的概念沒有階層可以展開**，只能做字串比對，
通常只搆得到個位數的論文——**那一軸等於不存在，而整條鏈會照跑、
看起來一切正常**。

實際發生過：某個概念對不到 MeSH，退化成一個沒有階層的詞，
交叉後只生出 6 個查詢（上限 10），整輪文獻層白跑。

### 每個概念必須並排呈現三件事

```
給的詞  →  解析到的 MeSH 描述詞（含識別碼）  →  該詞的論文數
```

**解析失敗要用明顯的錯誤態**，判定條件：

- 描述詞識別碼是 `null`（沒對到 MeSH），或
- 論文數低於下限（建議 100）

錯誤態要顯示替代詞建議（每個都附論文數），可一鍵替換。
替代詞由零成本的術語查驗端點提供。

### 互動

- 每個概念可**編輯**（改字後重新解析、即時更新論文數）
- 可**刪除**、可**新增**概念
- 顯示**預估會生出幾個查詢**（概念的交叉數，有上限）

### 送出

有任一概念仍在錯誤態時按鈕仍可按，但要先出現確認，
說明那一軸會失效以及後果。

## ③｜⏸ 審閱點三：可行性分級（**阻塞**）

**進入**：可行性分級跑完，鏈停在這裡。
**離開**：按下放行。**不放行就永遠停在這裡。**

**使用者在這裡做的決定：往下要驗幾個方向、辯幾輪。**

### 標頭

明確表示「⏸ 系統正在等你」。

### 主體：分級看板

四級 A/B/C/D：

- **A**：這週就能開始分析
- **B**：申請公開資料，幾週內能做
- **C**：要去弄新的資料
- **D**：現在做不到

**方向要分組，不可以重新排序**——組內維持錦標賽名次。

排序會讓人誤以為分級是一個單一的好壞分數，但它不是：
**可行性與新穎性是兩個獨立的軸**，最可行的方向完全可能已經被做過。
（實際發生過：可行性最好的那個方向，新穎性判定是已被搶先。）

#### A 級是 0 的時候要解釋

使用者沒有自己的資料時，A 級**結構上不可能**出現。
這不是錯誤，要用一句話說明，否則看起來像系統失效。

#### C 級的呈現重點不是那個字母

C 級唯一有用的資訊是**去路**。每個 C 級方向必須顯示：

| 欄 | 內容 |
|---|---|
| 缺什麼 | 變項名稱，照資料申請時的寫法（不是類別） |
| 去哪裡拿 | 具體的資料庫、聯盟或平台 |
| 怎麼拿 | 需要的權限或協議 |
| 多久 | 時間 |
| 多少錢 | 費用（若有） |

#### 每一列的但書

例如「欄位清單是描述版而非量測版，沒有查證過變項是否有值」。
**但書屬於那一列，不可摺疊。**

### 證據區（吃掉原本的 👁① 與 👁②）

視覺強度低於分級看板——這些是可以略過的背景資訊。
但**摘要行永遠可見**，只有明細可以收合。

#### 證據一：排名（原 👁②）

- 名次表：名次、方向題目、分數、分數差距的視覺化
- 對局數與比較方式：**每一對都判兩次、交換順序**（抵銷位置偏誤）
- **順序翻轉率**與合理區間——過低代表判準沒有鑑別力，
  過高代表判斷不穩定，**兩邊都是問題**
- **校準帶**：已知強度的錨點方向混在賽程裡（裁判分不出誰是錨點），
  顯示錨點是否落在正確的帶內、有無反轉
- **未判決的對局**：模型沒給出勝方的存為未判決、不猜。
  顯示數量並說明它們不影響分數

#### 證據二：去重（原 👁①）

- 摘要行：`N 組候選，判定 M 組重複`（**兩個數字都要有**）
- 展開後，每組顯示**兩邊完整的方向敘述**——
  不可以只給代號或截斷標題。判斷兩個方向是不是同一個，
  一定要兩邊都讀得到；實務上用代號與截斷標題根本判不了
- 每組可**推翻**系統判定
- `0 組重複` 是正常且常見的結果，措辭不要像錯誤

### 放行區

- 可調參數：**要驗幾個方向**、**辯論幾輪**
  （這兩個直接決定下游費用，而審閱點正是最該調整的時機）
- 往下三段的**預估費用**與**剩餘預算**
- 放行按鈕
- 旁支：**上傳資料清單**（就地展開面板，見第 5 節），上傳後重新分級

## ④｜⏸ 審閱點四：辯論紀錄（**阻塞**）

**進入**：辯論跑完，鏈停在這裡。**離開**：按下放行。

**使用者在這裡做的決定：放行、產出幾份報告。**

與 ③ 共用版型。標頭同樣是「⏸ 系統正在等你」。

### 每個被辯論的方向一個分頁

**分頁數必須等於實際被辯論的方向數。**
若有方向被選中卻沒有辯到，要明確點名。

這曾經是一個無聲的失效：巢狀迴圈沒重置，兩個方向被整個跳過，
**但所有守門都通過**——因為守門只數「發生過的回合」。

### 終止摘要（放最前面）

| 項目 | 說明 |
|---|---|
| 漂移分數 | 與門檻並列。**漂移是對照原始敘述算的，不是對照上一輪** |
| 實際輪數 / 上限 | |
| 終止原因 | 一句話 |
| 未解決的反對數 | |

**終止由系統從紀錄算出來，不是模型自稱打完了。**
這一點要寫在畫面上，否則使用者會以為輪數少代表沒認真跑。

漂移超標而終止時，要說明系統**拒絕採用**那個修訂版——
這是設計要的行為，不是失敗。

### 逐輪紀錄

一輪一組：

- **反對**（挑戰方）與**回應**（辯護方），兩邊角色要能分辨
- 該回合的**評分 1–5**（評分是對**反對的強度**，不是對回應的品質）
- 該反對是否**已解決**

### 評分分布

顯示分布並解釋意義：分布裡有高分代表那些反對是真有力的，
不是辯護方敷衍。

### 引用

辯論中引用的論文必須回頭比對實際檢索結果。
顯示引用數與捏造數（正常是 0）。

### 放行區

放行按鈕 + 要產出幾份報告 + 預估費用 + 剩餘預算。

## ⑤｜報告（含下載與撞題監看）

**進入**：報告產出後。**離開**：下載或回到 ①。

### 下載是明確需求，不是加分項

至少兩種格式：**PDF**（給人讀、給人傳）與 **Markdown**（給人改）。
**下載動作在畫面頂部就要看得到**，不要只放在最底下。

### 頂部摘要藥丸

至少三個：**新穎性判決**、**可行性等級**、**引用數與捏造數**。

新穎性判決四種，意義差很多，要能分辨：

| 判決 | 意思 |
|---|---|
| `no_prior_art` | 找不到前案 |
| `adjacent` | 沒人做過，但有鄰近文獻（**健康的結果**） |
| `incremental` | 有人做過很接近的 |
| `scooped` | 已經被做過了 |

### 八節（缺一不可，資料庫層有強制）

```
01 題目與問句        02 背景與缺口        03 方法草圖        04 引用文獻
05 新穎性判決        06 可行性與取得清單   07 未解決的反對    08 動手前要先讀什麼
```

每節有最低字數。左側或頂部要有節次導覽，長報告要能跳。

### 第 06 節要有一份不經模型的取得清單

除了模型寫的散文，另外顯示一份**直接從資料庫拉出來**的缺項清單，
並標明來源。

模型寫的那節是給人讀的散文，會漏；這一份不會，因為沒有東西重述它。
**兩份不一致時以資料庫那份為準**——這句話要寫在畫面上。

### 引用

每一筆要能點開驗證（DOI / PMID）。
**DOI 與 PMID 指向不同論文時兩個都不用**，這種情況若發生要標出來。

### 「這份沒有涵蓋什麼」（必要區塊，不可摺疊）

必須列出這一次執行的實際限制，至少涵蓋：

- **全文取得率**（拿到全文的篇數 / 總篇數）與它的後果
- 有多少方向**沒有驗證過新穎性**（未驗證 ≠ 新穎，且不參加排序）
- 有多少方向因為被判已做過而**被排除**，並點名是哪些
  （安靜地少寫一份報告，在輸出上跟「這個方向不存在」長得一模一樣）
- 辯論的實際輪數與未解決的反對

### 撞題監看（頁面底部一區，預設關閉）

- 開關
- 監看的查詢數、基線識別碼數、上次檢查時間、目前結果
- **成本模型要說明**：檢索與比對不花錢，只有真的冒出新論文時才叫模型
  （這決定使用者要不要開它）
- 被搶先時：明顯的警示，附上是哪個方向、論文標題與識別碼、發表日期，
  以及「這是不是真的撞題」的判定與理由
- `尚無新論文` 是好消息不是空資料，措辭要反映這一點

## 5. 資料清單面板（不是頁面，是就地展開的面板）

出現在 ① 的「我有資料」選項下，以及 ③ 的放行區旁邊。

### 一條紅線

**原始資料永遠不上傳。** 只上傳欄位清單。
畫面上要講清楚，而且範本的結構要讓人**不可能**誤傳病歷：
**一列是一個欄位，不是一個病人。**

### 兩條路徑

**路徑一：有實際的資料檔** — 指定本機路徑，由本機工具實際掃描，
量出每個欄位的缺失率、唯一值數、範圍。標記 `measured`。

**路徑二：只有欄位的描述** — 自由文字描述，由 AI 解讀成結構化清單。
標記 `documented`。

### 兩種來源必須分得出來，而且有硬性差異

**`documented` 的清單不得產生 A 級。**

A 級的定義是「這週就能開始分析」，而在沒有人查證過變項是否真的有值之前，
那是一個穿著量測外衣的猜測。從論文或資料字典抄一個樣本數填進去，
等級就是錯的，**而下游沒有任何東西分得出來**。

介面上：

- `documented` 的清單，缺失率／唯一值數／範圍等欄位**必須留空**，
  不可以讓使用者填，也不可以顯示成 0
- 警語出現在上傳當下，不是事後

### 範本下載

提供欄位清單範本（CSV）。**編碼必須是 UTF-8 BOM**，
否則中文在試算表軟體裡會是亂碼。

### 重新上傳

同一個專案可重複上傳（描述版之後換成量測版是常見流程）。
舊版本保留，不覆寫。

## 6. 不要做的事

- **不要把每一種後端輸出都給一個頁面。** 判準是「使用者在這裡要不要做決定」。
- **不要做成儀表板。** 這是研究者的旅程，不是維運的操作台。
- **不要把阻塞的放行區做得跟證據區一樣強。** 證據可以略過，放行不行。
- **不要把警語做成收合區塊。**
- **不要只顯示百分比而不顯示分母。**
- **不要用同一個視覺強度呈現「已驗證」與「未驗證」。** 未驗證不等於通過。
- **不要讓「空」和「還沒跑」長一樣。**
- **不要在前端存流程狀態。**
- **不要讓使用者按下一個註定被費用護欄擋掉的按鈕。**
