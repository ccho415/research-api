# 收集不設年份窗，5 年篩選只發生在顯示層

W2 對外部來源的每一次檢索都**不帶 `year_from`**。使用者要看的「近 5 年」是在結果排序
與呈現時才套用的篩選，庫裡照樣存全部。

反過來做很誘人——在 API 那一層就砍掉舊論文，回傳的東西更小、更貼近使用者想讀的。
但 `paper` 是**共用快取**：這一次沒抓進來的論文，不是這次看不到，是**永遠不會進庫**。
下游的 W7 新穎性檢查要用的時候一樣拿不到，而那正是最需要看得遠的一層。

具體的反例來自本專案自己的紀錄：一份 Deep Research 報告宣稱「CGM 與腸道菌相跨模態
聯合建模至今無人做過」，實際上被 **Zeevi et al., _Cell_ 2015**（800 人、CGM + 菌相 + ML、
1,931 次引用）正面佔據。以 2026 年為基準，5 年窗是 2021 年之後——**那篇會被濾掉**，
系統會回報「查無相關文獻」，然後把一個已經飽和的方向送進報告。

## 為什麼會讓人意外

使用者明確要求「最近 5 年」，而這個決定看起來像是沒有照做。它照做了，只是把篩選
移到了不會造成永久損失的那一層。一個未來的讀者看到 `year_from` 從未被設定，
會以為是漏了。

## 代價

庫會長得比較快，而且裡面有相當比例的論文使用者永遠不會在清單上看到。
以單人使用的規模這不構成問題；真正的代價是**每次呼叫回傳的 25 篇裡，
可能有幾篇是舊的而排不進顯示清單**，等於那幾個名額被浪費掉。
若之後發現這個浪費明顯，處理方式是把 `limit` 調高，不是把年份窗加回收集層。
