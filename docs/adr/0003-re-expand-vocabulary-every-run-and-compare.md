# 每次跑動都重新展開詞彙，並與上次比對

重跑同一個題目時，可以沿用上次存下的 MeSH 描述詞，也可以重新展開一次。我們重新展開，
把結果存進 `project.vocab_expansion`，並與前一版比對，不同就標記出來。

沿用比較誘人：它讓「第二次跑，論文重用率 > 60%」這個驗收條件變成一個乾淨的測試——
查詢一模一樣，回來的論文當然大部分都在庫裡。但它會**凍住一個錯誤**。MeSH 每年更新，
而我們的展開還要經過一層自己寫的排序（見 ADR-0001 之外的 Q6b 決定：`limit=30` 撈回來
再依標籤匹配品質與樹狀鄰近度排序取前 10）。**第一次展開如果選錯詞，沿用會讓它錯到永遠**，
而且錯得無聲無息——重用率會很漂亮，因為你每次都在重複同一個錯誤的查詢。

## 為什麼會讓人意外

存了展開結果卻不用它，看起來像是白存。它的用途不是快取，是**對照組**：
展開漂移本身是訊號，它告訴你 NLM 那邊改了什麼，或是你的排序邏輯改動造成了什麼後果。

## 代價

驗收測試變得比較難讀：重用率低下來時，要先看展開有沒有漂移，才知道是快取沒作用
還是查詢真的換了。這是刻意的——那兩件事本來就該分開看，混在一起的乾淨數字是假的乾淨。

`project` 因此多一欄 `vocab_expansion jsonb`。這是本專案第一次為了記錄而動 schema
（ADR-0001 刻意避開了），理由是這份資料綁在題目上，而不是綁在單次檢索上，
`search_query` 沒有它的位置。
