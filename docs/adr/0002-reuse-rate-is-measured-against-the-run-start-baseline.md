# 論文重用率以「跑動開始那一刻」為基準線

PRD 的驗收條件是「第二次跑同一個題目，論文重用率 > 60%」。`db.ingest` 原本每個查詢
各回一次 `cache_hit_rate`，而一個題目會扇出成 10 個查詢，彼此高度重疊——查詢 #1 撈回
的論文，查詢 #7 會再撈到一次，於是**第一次跑就會報出很高的重用率**。用那個數字驗收，
等於這道關卡永遠自動通過。

所以驗收數字改成：**跑動開始那一刻先取一次論文 id 集合當基準線**，之後回來的每一篇
只問一件事——它在不在那個集合裡。跑動內部的重疊改名為「跑動內重疊」，降級成診斷用。

## 為什麼會讓人意外

`ingest` 這個端點回傳的 `cache_hit_rate` 看起來就是那個驗收數字，名字也像。未來的讀者
會直接拿它去比 60%，然後得到一個看起來很好但沒有意義的結果。**這兩個數字都是對的，
只是回答不同的問題**，而它們的差距只有在同一個題目跑第二次的時候才看得出來。

## 代價

要在跑動開始時多做一次 `SELECT id FROM paper`，並把它帶在跑動的狀態裡。在目前的
語料規模上是一次索引掃描，可忽略；語料長到百萬篇時要改成比對 `paper.created_at`
早於跑動開始時間，而不是實際持有 id 集合。
