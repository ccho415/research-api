# 欄位清單填寫說明

這份表描述**你有哪些欄位**，不是你的資料本身。

一列 = 一個欄位。所以它在結構上就放不下病人資料：沒有任何一格是給「值」用的。
這是刻意的——如果範例長得像一張資料表，遲早會有人把真的病歷填進去然後上傳，
而臨床資料一旦進了伺服器就收不回來。

## 兩條路，先看你走哪一條

**如果你的資料是 `.csv` / `.tsv` / `.txt`，不要填這張表。** 跑這行就好：

```
python tools/inventory.py <資料夾> --pack observational --out inventory.json
```

它在你的機器上讀檔、算出缺失率、唯一值數、數值範圍和列的結構，
然後只輸出欄位資訊。**數字是量出來的**，可行性分級才判得準。

WES 的話要剖析的不是 BAM，是**變異呼叫之後那張表**（MAF 改副檔名成 `.tsv`）
和**臨床追蹤表**。那兩張是 MB 級的，不是幾十 GB。

**填這張表的時機**：資料還沒整理好、或格式不是分隔文字（資料庫、SPSS、
只有一份資料字典）。這條路存進去會標成 `documented`，
而**每一個可行性等級都會寫上「此清單未經量測」**。

## 欄位怎麼填

| 欄 | 填什麼 |
|---|---|
| `file` | 這個欄位屬於哪個檔案。同一個檔案的欄位用同樣的名字 |
| `column` | 欄位名稱，照你資料裡實際的寫法 |
| `dtype` | `string` / `number` / `category` / `date` 四選一 |
| `personal` | `yes` 代表這一欄能識別到個人（姓名、病歷號、身分證、生日、地址、電話）|
| `joins_on` | 這欄能連到別的檔案時填 `檔名:欄位名`，否則留空 |
| `description` | 一句話說明這欄是什麼。**這是最有用的一欄** |

## 不要填的東西

**不要填缺失率、唯一值數、最小值、最大值。** 那些只能從讀資料得到，
上傳時會被拒絕。

理由不是規則主義：可行性分級會用那些數字判斷「這個變項雖然存在，
但四成缺失所以做不了」。**填一個猜的進去，等級會偏樂觀，而下游沒有任何東西
分得出猜的和量的。** 誠實的空白比填好的猜測有價值。

## 一件跟你的題目直接相關的事

如果你要問的是「基因改變是否影響存活」，那**臨床追蹤表比變異表更關鍵**。
WES 給的是基因型那一半；存活時間、事件狀態、治療方案不在定序資料裡。

沒有那張表的話，可行性分級會把方向判成 C 級（可行，但要先取得臨床結果資料）。
**那是正確答案**——它告訴你瓶頸不在定序，在資料串接。
